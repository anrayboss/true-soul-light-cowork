# 智能互動心智圖系統 - 開發紀錄 Log (Development Log)

本文件完整記錄了「陳仲豪身心健康行銷變現課程心智圖系統」的開發歷程、使用者需求變更、功能實作細節以及核心技術問題的解決方案。

---

## 🛠 系統技術棧 (Technology Stack)
- **前端骨架**：HTML5 + Tailwind CSS (v3 class-based 暗色模式) + FontAwesome 6 (圖示庫)
- **心智圖核心**：D3.js (v7) + Markmap-view + Markmap-lib (Markdown 轉心智圖解析器)
- **版面配置**：自訂雙欄 Flexbox 佈局，支援響應式手機版（上下分割）與桌面版（左右分割），並配備觸控與滑鼠拖曳的分隔線調整機制。

## 歷次開發需求與實作紀錄 (Development Logs)

### 階段一：視覺優化與雙向游標連動

#### 1. 顏色與文字底線深度修復
- **需求**：解決切換主題或重載時，節點底線和連結線消失的 Bug。
- **實作**：修正了 `color` 存取器在渲染階段因為讀取不到 `node.depth`（此時應讀取 `node.state.depth`）導致連線隱形的問題。調整為優先讀取 `node.state.depth`（若無則回退至 `node.depth || 0`）。同時移除寫死的灰色設定，讓連線與底線動態套用深度主題色。

#### 2. 加大節點垂直行高
- **需求**：原版心智圖節點擠壓，閱讀性不佳，需將節點行距拉大至 1.5 倍。
- **實作**：在 `Markmap.create` 的設定選項中，將 `spacingVertical` 參數從預設的 `5` 調整為 `15`，有效拉開節點間距。

#### 3. 編輯器與心智圖雙向定位連動 (雙向游標同步)
- **需求**：希望編輯器游標移動到哪，心智圖就高亮並置中該節點；點擊心智圖節點時，編輯器也要跟著滾動並選取該行。
- **實作**：
  - **編輯器 -> 心智圖**：監聽編輯器 `click` 與 `keyup` 事件，藉由 `findActiveNodeForLine` 尋找最鄰近的節點。若節點已收合，透過 `unfoldAncestors` 自動將其所有祖先節點的摺疊標記重置（將 `fold` 設為 `0`），並使用輕量級的 `mm.renderData()` 進行重繪、高亮與置中聚焦。
  - **心智圖 -> 編輯器**：在 SVG 註冊 `click` 捕獲事件，點擊節點時，編輯器會自動滾動並選取對應整行文字，並計算字元範圍。

#### 4. 一鍵展開與恢復收摺
- **需求**：上方需要有按鈕可以一次性展開所有節點，展開後按鈕要變成「恢復預設」，讓使用者切換回初始只顯示兩層的狀態。
- **實作**：實作 `toggleExpandAll()`、`collapseAllNodes(node, depth)` 等控制函式。點擊時切換 `isAllExpanded` 狀態，遞迴重置所有子節點的 `payload.fold`。

#### 5. 雙擊行內編輯器與字元解碼
- **需求**：雙擊節點可以直接在心智圖上進行文字編輯，且不能產生亂碼。
- **實作**：
  - 將雙擊（`dblclick`）監聽器設於捕獲階段（`true`），繞過 D3 zoom 的 `stopPropagation` 阻擋，成功喚起 `#inline-editor`。
  - 編輯時使用臨時 `textarea` 對 HTML 實體字元（如 `&#x8ab2;`）進行解碼，轉回繁體中文，避免儲存時產生亂碼。

#### 6. 直線/曲線樣式切換
- **需求**：希望可以一鍵切換「直角折線」或「曲線連結」的樣式。
- **實作**：覆寫 D3 的 `linkHorizontal` 路徑產生器，引入 `window.useStraightLines` 全局控制。直角折線模式下計算 `x_mid = (x0 + x1) / 2`，生成 90 度直角彎折路徑（`M... L... L... L...`）。上方加入 `#btn-toggle-line` 按鈕進行切換並調用 `mm.renderData()`。

### 階段二：分欄拖曳、編輯器字型與手機版響應式設計

#### 7. 雙欄寬度可調式拖曳分隔線
- **需求**：雙欄分割模式下，中間的分隔線要可以自由拖曳調整比例。
- **實作**：
  - 在 DOM 中間插入 `#drag-bar` 元素，並設計 hover 亮起及膠囊型 grab 把手。
  - 實作 `setupDragBar()` 拖曳邏輯。拖曳時暫時停用右側 SVG 的指針事件（`pointer-events = 'none'`）避免 D3 畫布搶奪滑鼠，使拖曳非常平順。
  - 設計 `lastSplitPercent` 全局變數，記憶最後調整的分欄比例，在切換視圖模式時無縫復原。

#### 8. 編輯器文字改用黑體與標題前自動插空行
- **需求**：編輯器改用黑體，且所有 Markdown 標題（以 `#` 開頭的行）上方如果沒有空行，就自動加上一行空行。
- **實作**：
  - 將 `<textarea id="editor">` 的 class 類別從 `font-mono` 更換為 `font-sans`（黑體，預設微軟正黑體）。
  - 實作 `formatEditorHeadings()` 函式，在網頁初始化載入時，自動掃描每一行，若發現為標題且上方無空行，則主動為其插入一行空行，保持排版層次清晰。

#### 9. 編輯器字級放大至 1.5rem
- **需求**：將編輯器字型放大至 1.5rem。
- **實作**：將編輯器 `<textarea>` 的 Tailwind 類別由 `text-sm` 更換為 `text-2xl`（即 24px，1.5rem）。

#### 10. 行動端（手機版）佈局與漢堡選單
- **需求**：設計手機版佈局：橫幅只留標題文字，按鈕全放入右側純色漢堡選單內；雙欄改上下分割且一樣可拖曳調整。
- **實作**：
  - **橫幅響應式**：使用 Tailwind 的 `md:flex` 與 `hidden` 類別，在手機版隱藏一般按鈕工具列。標題區塊設為 `flex-wrap` 與適度縮小的字級，確保在極小螢幕上不溢出。
  - **純色漢堡選單**：右側新增 `#btn-mobile-menu` 漢堡按鈕，點擊後從右側滑出純色不透明的面版（淺色：`bg-white`，深色：`bg-slate-800`，無毛玻璃效果），收納所有功能。選單狀態與桌面端同步。
  - **上下分割與觸控拖曳 (Touch Support)**：在 `@media (max-width: 767px)` 中，主版面改為 `flex-direction: column`。拖曳分隔線改為水平橫條，游標變更為 `row-resize`。
  - 在 `setupDragBar()` 整合觸控事件（`touchstart`、`touchmove`、`touchend`），拖曳時調用 `e.preventDefault()` 停用頁面滾動，防止瀏覽器手勢干擾，並以 `lastSplitPercentMobile` 記憶手機版高度比例。

#### 11. 手機版折疊式 i 提示按鈕
- **需求**：為手機版設計對應的操作說明，且預設為左上角一個小 i 圓型按鈕，點擊才展開提示。
- **實作**：

  - 點選按鈕後向右滑出提示面版（`#info-tooltip`），並會自動根據目前螢幕尺寸顯示電腦版或手機版的專屬操作指南。
  - 實作空白處點擊收合（點選頁面其他任何地方自動將提示面版收摺）。

#### 13. 線條樣式切換失效修復 (載入順序 Bug)
- **問題**：拆分檔案後，發現直線與曲線的切換功能失效。
- **原因**：因為 `markmap-view` 會在載入時擷取並編譯 D3 原生的 `d3.linkHorizontal` 產生器。如果將 `script.js` 放在 `<body>` 底端載入， override 的動作會慢於 `markmap-view` 的載入時間點，導致 D3 覆寫失效。
- **解決方案**：
  - 將 HTML 中 `<script src="script.js"></script>` 移至 `<head>` 中，置於 `d3@7` 載入之後、`markmap-view` 載入之前。
  - 為了防止在 `<head>` 載入 JS 時因為 DOM 元素尚未產生而報錯，將 `script.js` 中唯一的頂層 DOM 事件監聽（編輯器 input 監聽器）安全地移入了 `setupEditEvents()` 內。

#### 14. 編輯時折疊狀態保留與防抖深度修復 (探索與解決過程)
- **問題現象**：使用者在打字編輯、或點擊右鍵選單新增/修改子節點時，發現所有已展開的子節點會在一瞬間「自動收合」回初始狀態（即只展開到第二層），而且視角會伴隨 `mm.fit()` 產生討厭的重置跳動。
- **排查與解決過程**：
  1. **初步診斷（呼叫鏈重置）**：
     發現每次編輯文字都會觸發 `editor` 的 `input` 事件，在延遲 300ms 後呼叫 `updateMarkmap()`。其內部的 `mm.setData(root)` 會用新 parsed 的 `root` 來重新建構心智圖，這會完全抹除所有在執行期動態產生的 `payload.fold` 展開/摺疊標記，使其回到 `initialExpandLevel: 2` 的預設值。
  2. **第一次修復嘗試（失敗）**：
     * *做法*：實作了 `saveFoldState(mm.state.data)` 函式，以節點的 `content` 作為 key，快照現有心智圖的摺疊狀態；並在 `mm.setData(root)` **之前**，呼叫 `restoreFoldState(root, foldSnapshot)` 還原回新 parsed 的 `root`。
     * *結果*：**依然會自動摺疊**。這是因為 `mm.setData(root)` 本身在內部處理時，會自動遍歷並重置新 `root` 上的所有摺疊標記，導致在 `setData` 之前做的狀態還原被完全覆蓋。
  3. **深層診斷與瀏覽器驗證（成功）**：
     * 我們透過瀏覽器環境進行實地排查，確認 `mm.setData` 會忽視 `root` 身上的 `fold` 屬性，重新強制套用實例的 `initialExpandLevel` 來重設內部狀態。
     * 只有在 `mm.setData(root)` **之後**，直接去修改 Markmap 實例當前運作的 `mm.state.data`，才能成功寫入我們想要的摺疊標記。
  4. **最終正確的解決方案**：
     * **順序重組**：調整 `updateMarkmap(isFirstLoad)` 的處理順序，先執行 `mm.setData(root)`（這會建立新資料結構但抹除 fold 標記）。
     * **覆寫實例狀態**：在 `setData` 執行完後，再呼叫 `restoreFoldState(mm.state.data, foldSnapshot)`，將摺疊快照強行覆寫到實際的 `mm.state.data` 上，最後呼叫 **`mm.renderData()`** 刷新渲染。
     * **防抖控制**：配合 `isFirstLoad` 旗標，只在「首次載入」時調用 `mm.fit()`，其餘編輯更新時皆跳過 `fit`，從而完美阻斷視角抖動。
     * **結果**：編輯與新增節點時，展開/摺疊狀態完美保留，完全不再有自動收摺與畫面跳動的現象！

#### 15. 空白處右鍵新增「獨立主主題」功能
- **需求**：滑鼠在心智圖空白區域按右鍵時，能新增一個獨立的主主題父節點。此外，文字編輯區也要能新增獨立主主題，避免其依附在最初始的根節點下。
- **解析與實作**：
  - **編輯器語法解析**：在 Markmap/Markdown 階層中，第一行 `# <標題>` 是整個心智圖唯一的根節點。任何後續以兩個井字號 `## <主題名稱>`（Level-2 Heading）開頭的行，皆會自動被編譯為直接隸屬於根節點下的第一級分支（即獨立的主主題父節點），而不會嵌套在其他子節點下。
  - **右鍵空白處觸核**：
    - 在 `setupEditEvents()` 的 `contextmenu` 事件中，透過 `e.target.closest('.markmap-node')` 判斷點擊位置。
    - **點擊節點時**：顯示「編輯節點」、「新增子節點」、「新增同層節點」、「刪除」選項，隱藏「新增獨立主主題」。
    - **點擊空白區域時**：隱藏節點操作選項，僅顯示「**新增獨立主主題**」選項。
  - **動作實作 (`menuAddParentTheme`)**：點擊選項後，在文字編輯器尾端自動追加 `\n\n## 新獨立主題`，呼叫 `updateMarkmap(false)`，滾動編輯器至最底部，並在 400ms 後對新生成的節點喚起行內編輯器，引導使用者命名，操作體驗非常自然。
